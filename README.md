# This repo is for split hoverboard with MM32SPIN0X/2X MCU
 You can help us by testing this code on actual hardware

 Pre-compiled binary is available


## Building from source

Two separate builds live here:

| What | Where | Toolchain |
|------|-------|-----------|
| Board firmware | `HoverBoardMindMotion/` | CMSIS-Toolbox + Arm Compiler 6 |
| Wi-Fi remote | `esp32-remote/` | PlatformIO ([its own README](esp32-remote/README.md)) |

### Firmware prerequisites

Everything is version-pinned, so a fresh machine resolves the same toolchain:

- `HoverBoardMindMotion/vcpkg-configuration.json` pins Arm Compiler 6.24, CMSIS-Toolbox 2.14.1,
  CMake 3.31.12 and Ninja 1.13.2, all from Arm's artifact registry.
- `Hoverboard.csolution.yml` pins the packs `ARM::CMSIS@^6.3.0` and
  `MindMotion::MM32SPIN2x_DFP@^1.1.6`; `Hoverboard.cbuild-pack.yml` records the exact versions
  that were resolved (6.3.0 and 1.1.6).

You must supply two things yourself, because they cannot live in the repo:

1. **An Arm Compiler 6 license** for `armclang`. Check Arm's current terms — a free community
   licence covers non-commercial use, and Keil MDK editions include one.
2. **SEGGER J-Link software**, for `JLinkExe` and `JLinkGDBServerCLExe`. On Linux its package
   also installs `/etc/udev/rules.d/99-jlink.rules`; your user must be in the `plugdev` group
   or the probe is invisible to everything but root, with no useful error.

You do *not* need a separate GNU Arm toolchain: `arm-none-eabi-gdb`, which `launch.json` calls,
ships inside the `arm.vscode-cmsis-debugger` extension. Likewise `cbuild` and `csolution` are put
on PATH by the Arm environment manager only inside VS Code — they will not be on your PATH in a
plain terminal, which is normal.

### Firmware build (VS Code)

The project is wired for VS Code and the Keil Studio extensions; open the repo and accept the
recommended extensions ([.vscode/extensions.json](.vscode/extensions.json)).

1. The Arm environment manager reads `vcpkg-configuration.json` and downloads the pinned tools
   into `~/.vcpkg` on first activation.
2. The CMSIS Solution extension resolves and downloads the packs into `~/.cache/arm/packs`.
3. Pick the target in the CMSIS view and build. Output lands in
   `HoverBoardMindMotion/out/Hoverboard/<target>/<build-type>/`.

Targets are **SPIN27** (master) and **SPIN27-Slave** (same PCB, defines `BOARD_SLAVE`, addressed
through the master — see `Inc/board_config.h`). Build types are **Debug** (`-O0`) and **Release**
(`-O1`), both with debug info.

### Flashing and debugging

With a J-Link on the SWD pads (see [extraFiles/swd-mm32.png](extraFiles/swd-mm32.png)), the
tasks in [.vscode/tasks.json](.vscode/tasks.json) do the work: **CMSIS Load**, **CMSIS Erase**,
**CMSIS Run**, **CMSIS Load+Run**. The *JLink (launch)* and *JLink (attach)* debug
configurations attach GDB to a server on port 3333.

SWD runs at 1 MHz deliberately: at 4 MHz the target was occasionally lost while the motor ran.

### Code navigation

`clangd` reads `HoverBoardMindMotion/.clangd`, which points at the compilation database under
`out/`. **Build once before opening C files**, or clangd will have nothing to read and will flag
every include.

### Generated files, not in git

`out/`, `tmp/`, `build/`, `RTE/_Debug_*`, `RTE/_Release_*`, `.cmd.jlink`,
`HoverBoardMindMotion/.vscode/cmsis.json` (which target is selected) and `esp32-remote/.pio/`
are all regenerated by the tools. The `RTE/_MM32SPIN05|06|25/` directories
*are* tracked — they are from the original Keil project.

`esp32-remote/include/secrets.h` holds your Wi-Fi credentials and is deliberately untracked;
copy `secrets.example.h` over it before the first ESP32 build.

## Working features

The firmware is already 90% functional, basic motor control should all work, but more testing is needed

https://youtu.be/hCaIlEKzI3A
* compatiable with 99.9% of boards without recompile
* working method to unlock and flash the mcu
* motor and hall sensor commutation
* RemoteUartBus protocol(used by gen2.x gd32)
* PID loop for constant speed
* self hold
* voltage and total current
* software and hardware over current protection
* sine wave mode to drive the motor with more torque and higher effiency
